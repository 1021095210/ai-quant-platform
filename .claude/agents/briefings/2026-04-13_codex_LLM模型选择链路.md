## 为什么这样做（Why）

- 用户已经明确要求：每个使用 LLM 的模块都要允许自主选择模型。
- 平台当前同时存在：
  - 已可用的 OpenAI-compatible 运行时
  - 未来可能接入的 DeepSeek / 火山方舟
- 所以本轮采用“统一 profile 列表 + 模块显式选择 + 运行时解析”的方案，而不是把模型选择写死到单个模块里。
- 关键设计权衡：
  - **模型选择只作用于理解/生成层**
  - **平台真值层、硬校验、生成资格、人工确认流不能被模型选择绕过**
- 对火山方舟没有直接切运行时，因为仅有 key 还不足以发起调用，仍需要 `model / endpoint_id`。
