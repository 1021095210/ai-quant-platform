## 为什么这样做（Why）

第一阶段已经固定了 API 形态，但最大缺口仍然是“任务状态和策略版本重启即丢”。如果不先解决持久化，后续接入真实 worker、Redis 和 PostgreSQL 的收益会被内存状态掩盖。

- 先用 SQLAlchemy 抽象持久化，是为了同时兼容 SQLite 测试和 PostgreSQL 演示环境。
- 保留内存仓储实现，是为了后续做更细粒度单元测试或离线 mock 时仍有轻量方案。
- 改成工厂式启动，是为了消除导入模块时的数据库副作用，也更适合多环境配置。
