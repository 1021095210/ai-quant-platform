## 为什么这样做（Why）

- 先采用 FastAPI 直接托管静态页面，而不是再拆一个单独前端工程
  - 这样能最快交付一版可试用网页，并降低一周项目的前端构建复杂度
- 先把策略生成、回测、复盘打通成一条可演示主链路
  - 当前阶段目标是让用户真实点开网页就能走通核心流程，而不是只看 API 文档
- 复盘结果改为基于交割单统计生成
  - 用户看到的结果不再是纯假数据，更接近产品真实价值
- 保留回测和优化的异步任务资源模型
  - 为后续替换成真实 Worker / Redis 队列保留接口稳定性

需要后续 agent 注意的权衡：

- 网页端目前是静态 HTML + 原生 JS，不是 React 工程
- 策略生成仍是规则模板生成，不是真实 LLM
- 回测和参数优化仍是模拟结果，不是真实行情执行
- 复盘分析已读真实上传记录，但特征工程仍较浅
