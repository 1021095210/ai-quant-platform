## 为什么这样做（Why）

上一个阶段已经完成“产品是什么”的定义，这一步补的是“实现时先做什么、接口长什么样、数据怎么落、页面如何串起来”。

- 页面文档优先，是为了避免实现时前后端对工作台结构理解不一致。
- API 详细设计优先，是为了把自然语言策略、回测、复盘三条链路的输入输出固定下来，减少联调返工。
- 数据库直接给 SQL，而不是只写表结构说明，是为了让实现阶段可以直接建库，而不再做二次翻译。
- 五日拆解保持 2 到 4 小时粒度，是为了贴合培训节奏，而不是给一个过粗的甘特图式计划。

需要后续 agent 注意的权衡：

- 当前 SQL 设计偏演示版，使用 JSONB 提高迭代速度，不代表最终生产化模型。
- API 设计默认单用户研究工作台，不包含复杂权限、实时风控和多市场接入。
