## 为什么这样做（Why）

当前真正缺的不是更多设计文字，而是一个能承载后续真实实现的最小工程骨架。

- 优先落后端，是因为平台化增强版设计里最关键的变化就是“长任务资源化”和“状态管理”，这部分必须先体现在接口层。
- 选择内存仓储 + 模拟执行器，是为了先固定 API 形态和任务生命周期，后续再无痛替换成 PostgreSQL / Redis / Worker。
- 选择把测试直接接到 `python3 -m unittest`，是为了不破坏当前工作区已有的测试入口。

权衡：

- 当前还没有接真实 LLM、真实回测引擎、真实数据库和 Redis 队列消费逻辑。
- 这一步更像“平台后端骨架落地”，不是功能完整的可用产品。
