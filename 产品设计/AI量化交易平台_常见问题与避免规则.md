# AI量化交易平台常见问题与避免规则

> 最近更新时间：2026-04-02 13:00 UTC  
> 用途：沉淀这几天开发中反复出现的问题、根因、避免规则和每轮开发自检清单。  
> 维护规则：以后每轮开发结束后，如果出现新的重复问题，必须更新本文件，而不是只在聊天里临时说明。

## 1. 文件定位

这不是产品功能设计稿，而是长期维护用的“开发与接力防错文件”。

适用对象：

- 当前开发 agent
- 后续新接力的 agent
- 需要快速理解“哪些坑已经踩过、不能再踩”的维护者

## 2. 反复出现的常见问题

### 2.1 前端脚本语法或启动错误导致页面一直加载

典型现象：

- 规则模块一直停在“正在加载多市场默认规则”
- 金融导师一直停在“正在加载导师问题卡片”
- 页面 HTML 能打开，但核心内容完全不渲染

已出现过的真实根因：

- `rules.js` 中残留非法逗号，浏览器解析失败
- `mentor.js` 中用了非法的 Python 风格参数写法，浏览器直接 `SyntaxError`

避免规则：

- 改任何前端模块脚本后，不能只看接口是否通
- 必须至少做三层检查：
  1. `node --check`
  2. stubbed DOM 启动测试
  3. 真实页面加载验证

### 2.2 浏览器缓存导致用户仍命中旧脚本

典型现象：

- 本地代码已修复，但用户打开页面仍看到旧问题
- HTML 还在引用旧版 `js` 资源

避免规则：

- 前端关键脚本修复后，需要提升资源版本号
- 当前已经用过的做法：
  - `mentor.js?v=20260402c`
  - `shared.js?v=20260402c`
- 修复后必须确认页面实际输出的是新版本脚本路径

### 2.3 只看单测，不做真实链路验证

典型现象：

- 测试通过，但用户一点击还是坏
- 接口返回正常，但按钮、卡片、下一步引导仍然不能用

避免规则：

- 关键模块修复后必须补真实链路验证
- 当前高优先级真实验证模块：
  - 规则模块
  - 金融导师
  - 回测中心
  - 交易复盘
  - 管理后台

### 2.4 页面交互不符合真实用户习惯

典型现象：

- 上一步完成后，下一步按钮仍然是灰的或不明显
- 页面给出的语言像开发说明，不像成熟平台
- 信息顺序不适合新手用户阅读

已被多次指出的方向：

- 生成完成后，保存或下一步按钮要点亮
- 新手先看结果和曲线，再看配置摘要和执行边界
- 模块头部介绍要像成熟 Web 应用平台，不要像内部说明

避免规则：

- 有流程依赖的按钮必须用显式状态表达：
  - 禁用态
  - 可点击态
  - 完成后下一步点亮
- 任何文案如果像“系统开发备注”而不像用户语言，都应收敛

### 2.5 交易语义与市场制度不一致

典型现象：

- A股现货场景出现“建议做空”
- 页面直接显示 `t_plus_one`、`undefined`、`raw` 这类内部值
- 复盘或回测解释里出现英文内部枚举而不是中文含义

避免规则：

- A股现货默认按单向“买入后卖出”理解
- 不要直接把内部枚举暴露给用户
- 所有市场能力和制度边界都要先转成明确中文

### 2.6 历史数据兼容问题导致后台或汇总页报错

典型现象：

- 管理后台汇总接口在旧库数据上 500
- 新代码能跑新数据，但读历史记录时报错

已出现过的真实根因：

- 旧任务状态是 `completed/cancelled`
- 旧时间字段存在 naive datetime

避免规则：

- 平台状态枚举升级后，要保留必要的兼容映射
- 汇总类逻辑处理时间比较时，要考虑 naive / aware datetime 混用
- 后台相关改动后，必须补旧数据兼容测试

### 2.7 外链不可用或失效后没有重新验证

典型现象：

- 给用户发了链接，但已经失效
- 页面功能已经修复，但外链没有同步更新

避免规则：

- 每轮改动结束后，先验证再发链接
- 至少验证：
  - `/healthz`
  - 当前模块页面
  - 如涉及登录模块，则验证登录后接口
- 当前外链是临时隧道，不要把它当永久部署

### 2.8 文档只堆总文件，后续接力难定位

典型现象：

- 主接力文件越来越长
- 新 agent 很难快速知道某个模块到底做到哪一步

当前解决方案：

- 主文件仍保留：
  - `AI量化交易平台_新环境恢复与Agent接力说明.md`
- 具体模块拆到：
  - `产品设计/接力模块/`

避免规则：

- 以后模块改动不能只更新总接力文件
- 必须同步更新对应模块文件

### 2.9 只改代码，不同步接力与简报

典型现象：

- 代码变了，但新 agent 不知道为什么这样设计
- 下一个接力者只能重新翻代码猜上下文

避免规则：

- 每轮任务结束后，必须同步更新：
  - GitHub 代码
  - 仓库内 briefings
  - 主接力文档
  - 对应模块接力文件
- 必要时同步仓库外镜像

### 2.10 把运行态数据库误当代码基线

典型现象：

- 本地验证后 `quant_platform.db`、`market_data.db` 有变更
- 容易误以为这些也该提交

避免规则：

- 运行态数据库不是代码基线
- 除非未来明确要纳入样例数据库，否则不要提交这两个文件

## 3. 每轮开发前自检

开始动手前先看：

1. 当前改动涉及哪个模块
2. `产品设计/接力模块/` 下对应文件是否已存在
3. 类似问题是否已经在本文件里出现过
4. 这轮是否会影响：
   - 用户按钮状态
   - 市场语义
   - 页面加载链路
   - 管理后台兼容
   - 外链验证

## 4. 每轮开发后自检

改动结束后至少确认：

1. 功能本身可用
2. 测试已补
3. 关键前端脚本可启动
4. 页面真实加载正常
5. 用户可理解的文案没有退回内部术语
6. 接力文档已同步
7. 对应模块文件已同步
8. 简报已写
9. 外链已验证

## 5. 遇到同类问题时的默认处理顺序

如果用户反馈“这个模块加载不出来”或“还是不对”，默认按这个顺序排查：

1. 看浏览器实际加载的脚本版本
2. 看接口是否返回正常
3. 看前端脚本是否有语法错误
4. 看模块是否能在 stubbed DOM 下启动
5. 看是否命中了旧缓存
6. 看是否是旧数据库兼容问题

## 6. 后续维护要求

以后继续开发时，如果出现以下任意情况，必须回写本文件：

- 同类问题第二次出现
- 某个模块出现新的高频故障模式
- 某条避免规则需要升级成硬性检查项
- 某个用户体验问题被反复指出两次以上
