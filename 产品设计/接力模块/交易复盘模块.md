# 交易复盘模块

## 当前定位

- 路由：`/replay`
- 角色：把真实交易样本转成可复用的改进建议

## 当前已实现

- 支持三种数据来源：
  - CSV 导入
  - 成交截图
  - 手动录入
- 上传方式当前已改成“按钮切换 + 单一模式内容区”：
  - 点击 `CSV 导入` 时，只显示 CSV 文件上传与直接粘贴 CSV
  - 点击 `成交截图` 时，只显示截图识别与截图登记所需字段
  - 点击 `手动录入` 时，只显示手动补录表单与手动记录列表
  - 2026-04-14 已补前端隐藏样式，三种模式当前不会再同时叠在一起显示
- 上传方式区当前已补更明确的模式引导：
  - 当前方式标题
  - 适用场景说明
  - 建议顺序步骤提示
  - 选中方式的强化视觉态
- 当前较长任务已支持后台异步模式：
  - 长文字智能识别会转入后台解析
  - AI 复盘分析会转入后台执行
  - 用户可以先切到其他模块继续使用
  - 完成或失败后会弹出小消息提醒
  - 输入区上方会显示就近状态提示，不再只放在页面顶部横幅
  - 复盘页当前已新增“后台解析任务”中心，可回看最近长文字识别任务并重新打开结果
  - 成交截图 OCR 当前也已接入同一套后台任务中心，可回看最近截图识别任务并重新打开结果
  - 2026-04-15 已继续补齐任务中心可用性：
    - 当前支持按 `任务类型 / 任务状态` 筛选
    - 当前支持对失败任务直接点击“重试”
    - 当前会显示任务进度条、进度百分比和当前阶段说明
- 手动录入当前已拆成两条子流程：
  - 长文字智能识别
  - 逐笔手动补录
- 逐笔手动补录当前已补字段：
  - 买入价格
  - 卖出价格
  - 买卖手数
- 长文字智能识别当前支持：
  - 当前后端已兼容市场别名输入：
    - `A股 / 中国股票 / cn_a_share` 会统一归一化成 `cn_equity`
    - 避免接口层或后续外部调用因市场值写法不同而误报“未识别到股票代码”
  - 当前已进入“确定性解析 + AI 混合解析 + 人工确认”模式第一阶段：
    - 先用规则解析器识别日期块、代码、显式买卖规则
    - 如果环境里配置了可用 LLM，会进一步用 AI 补复杂自然语言规则
    - AI 解析结果不会直接入库，仍然必须经过：
      - 代码合法性校验
      - 日期合法性校验
      - 规则映射
      - 真实行情补价
      - 用户人工确认
    - 当前页面会显示：
      - 解析方式（规则解析 / AI 混合解析）
      - 当前使用的模型标签
      - 需要重点确认的警告
      - 输入真值摘要（记录数、待人工确认数、补全字段和冲突标记）
      - 验收摘要：
        - 当前是单批次还是分组批量样本
        - 请求日期块与实际识别日期块数量
        - 识别日期列表
        - 待确认记录数
        - 真实行情补价字段数
        - 推断的入场 / 离场 / 盈亏字段数
  - 当前页面已新增 `模型选择`：
    - 统一从 `/api/v1/platform/llm-profiles` 读取可用模型配置
    - 当前主要作用于“长文字智能识别”的 AI 混合解析层
    - 当前火山方舟默认候选模型约定为：
      - `deepseek-v3-2-251201`
    - 如果显式选择的模型当前不可用，系统会诚实回退到模块默认模型
  - 支持“多日期分组清单 + 全局买卖规则”批量解析：
    - 每个 `YYYY-MM-DD` 日期块下可挂一组股票代码
    - 文末可统一写“以上日期买入 / 买入方式 / 卖出方式”
    - 系统会按日期块批量生成成交记录，而不是只取全文第一个日期
  - 支持“多日期分组清单 + 各日期块独立买卖规则”解析：
    - 每个日期块当前都可单独写自己的 `买入方式 / 卖出方式 / 卖出日期`
    - 日期块内局部规则优先级高于全文统一规则
    - 如果某个日期块没有局部规则，才回退到全文统一规则
    - 如果全文也没有显式买入规则，当前仍会保守回退到 `当日开盘价买入`
  - 识别完成后当前会在页面里额外输出“长文字识别摘要”：
    - 识别到多少个日期块
    - 每个日期块加入了多少笔记录
    - 每个日期块识别到的买入规则和卖出规则
    - 每个日期块对应的标的列表
    - 类似 `600501con9.SH`、`002174.SZfinalsell` 这类带尾缀噪音的代码，当前会尽量清洗成标准代码
    - 明显无效代码如 `000.SH` 当前会自动忽略
  - 从整段文字里识别 `YYYY-MM-DD`
  - 也可识别 `YYYY/MM/DD`
  - 识别一组 A股代码，如 `603590.SH, 002225.SZ`
  - 也可识别不带交易所后缀的 6 位 A股代码，如 `603590, 002225`
  - 识别买入规则：
    - 当日开盘价买入
    - 当日收盘价买入
    - 次日开盘价买入
    - 次日收盘价买入
    - 第 N 个交易日开盘价买入
    - 第 N 个交易日收盘价买入
    - 显式买入价
  - 识别卖出规则：
    - 当日收盘价卖出
    - 次日收盘价卖出
    - 第 N 个交易日收盘价卖出
    - 最低价低于“当日开盘价 - N 倍 ATR”时卖出
    - 价格低于“买入后任何一天的开盘价 - N 倍 ATR”时卖出
    - 上涨 N% 止盈卖出
    - 下跌 N% 止损卖出
    - 显式卖出价
  - 识别显式买入日期 / 卖出日期
  - 基于真实日线行情自动补全：
    - 买入价
    - 卖出价
    - 盈亏
  - 对超大分组文本当前已启用确定性快速路径：
    - 当日期块很多或总代码数很多时，会跳过慢速 LLM 混合解析
    - 仍保留分组、规则、代码清洗和记录生成
    - 避免大段文本长时间等待后失败
  - 对超长分组文本当前会按日期块自动分块解析后再合并结果：
    - 默认每块最多约 `4` 个日期块或 `24` 个代码
    - 当前摘要会显示后台分块数量，便于用户判断长任务是否正常执行
  - 用户提供的大样本长文本当前已实测可成功解析：
    - `21` 个日期块
    - `193` 笔记录
    - 约 `0.37s`
    - 当前会正确识别全局规则 `价格低于买入后任何一天的开盘价-0.5倍atr时卖出`
  - 自动补价来源当前会写入记录说明，便于确认是平台内部哪条数据链路补全
- 当百分比止盈 / 止损在当前数据范围内未触发时，当前也会明确说明“未触发阈值，已按后续可用收盘价补全”，不再退回含糊说明
- 智能识别出的记录当前会直接加入手动记录列表，用户确认后再统一提交复盘
- 成交截图当前已补 `OCR 第一阶段`：

## 当前设计约束

- 面向新手用户，按钮亮起状态必须明确反映下一步
- 不要把三种上传方式的全部表单同时摊在一个区域里
- 当前方式必须显式告诉用户“你正在用哪一种上传方式”和“下一步该做什么”
- 手动模式内部也要继续维持“智能识别”和“逐笔补录”的清晰分工，不能重新混成无结构的大表单
- A股现货默认按单向买入后卖出理解
- 自动补价、规则识别和盈亏推导，默认优先使用平台内部 ClickHouse / 平台数据中心，不应直接以原始外部接口结果作为用户侧真值
- 截图 OCR 目前还是第一阶段，识别后必须允许用户人工确认和改写，不能直接静默入库
- 长文字 AI 混合解析当前依赖稳定的结构化 JSON LLM 输出链路；如果环境里没有可用 LLM，会诚实回退到纯规则解析
- 模型选择只能影响“复杂自然语言规则理解”，不能绕过：
  - 代码合法性校验
  - 日期合法性校验
  - 真实行情补价
  - 用户人工确认
