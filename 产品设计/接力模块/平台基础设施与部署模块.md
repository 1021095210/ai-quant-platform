# 平台基础设施与部署模块

## 当前定位

- 角色：统一平台后端、数据、部署、日志、环境差异处理

## 当前已实现

- 技术栈已收口：
  - 前端：FastAPI 托管的多页面 HTML + Vanilla JS + CSS
  - 后端：Python + FastAPI + SQLAlchemy
  - 数据：SQLite 起步，支持 PostgreSQL / Redis / MinIO 生产基线
- 已补 Dockerfile、compose、外部依赖配置、环境模板、Caddy 示例
- `healthz` 已返回部署关键状态
- 管理员后台已接入应用日志
- 市场数据链路当前已支持“内部 ClickHouse 优先”的 A股接入第一阶段：
  - 通过环境变量配置 ClickHouse 主机、端口、账号、密码
  - 应用优先读取内部 `DWD`
  - 外部源改成回退补数链路

## 当前设计约束

- 生产环境默认应关闭测试账号
- 生产环境必须使用正式管理员初始化方式
- 临时外链只用于验证，不等同正式部署
- 普通 `git push` 当前仍不稳定，远端同步继续以 GitHub API 方案为准
- 反复出现的开发故障与排查规则，统一维护在 `产品设计/AI量化交易平台_常见问题与避免规则.md`
- 平台要走高可信实战路线时，资源、验收标准和已提供资源登记统一维护在 `产品设计/实战落地参考/AI量化交易平台_实战落地资源清单与验收标准.md`
- 数据接入默认基线已收口为“平台统一数据中心 + 增量同步 + 用户只读内部数据”，见 `产品设计/实战落地参考/AI量化交易平台_数据中心与增量同步设计.md`
- 如果读取内部 ClickHouse 数仓，默认优先使用 `ADS / DWD`，`ODS` 只做原始回查、补数、审计和重算输入
