# AI量化交易平台资源源选型建议

> 更新时间：2026-04-07 UTC  
> 目标：给“实战落地资源清单与验收标准”里的所有关键资源提供简明选型建议。  
> 原则：没有单一源能保证绝对正确。正式方案必须采用“主源 + 备用源 + 官方回查 + 证据链”。

补充：

- 如果内部已经有可维护的正式数据仓库，优先让平台读取内部数据仓库，再把外部接口作为后台补数和校验来源。
- 如果内部仓库已经按 `ODS / DWD / ADS` 分层，平台默认优先读 `ADS / DWD`，`ODS` 只做原始回查、补数和审计。

---

## 一、直接结论

### 数据调用方式

- 不让用户请求直接打上游接口
- 所有上游源只供平台后台任务使用
- 用户只读平台内部数据中心
- 平台内部做增量更新、快照冻结、双源校验
- 如果已有内部数据仓库，优先先接内部数据仓库
- 如果内部仓库已完成 `ODS / DWD / ADS` 分层，默认读 `ADS / DWD`
- `ODS` 不作为用户侧研究、回测、复盘、导师的默认查询层

### 现在最值得落地的高性价比方案

- A股行情：`Tushare Pro` 主源 + `AkShare` 备用 + `上交所/深交所/巨潮资讯` 回查
- 美股行情：`Alpaca` 主源 + `SEC EDGAR` 公告/财务真值 + `FRED/ALFRED` 宏观
- 加密行情：`Binance 官方 API` 主源 + 第二交易所官方 API 备用
- 新闻资讯：`官方公告源` 优先 + `NewsAPI` 这类聚合器补充，不把聚合器当真值源
- 市场规则资料：优先 `交易所 / 监管 / 官方规则文件`
- 历史真值样本：优先内部真实样本库，其次脱敏历史样本
- OCR：先用 `OCR 服务 + 人工确认流`
- 券商/执行：先接 `沙盒/纸面交易接口`
- 基础设施：`PostgreSQL + MinIO + Redis`
- 统一数据层：自建平台数据网关，参考 `OpenBB` 的 provider 结构
- LLM：保留 OpenAI 兼容链路，但必须做引用式回答，不把 LLM 当真值源

### 如果要更高可信

- A股主源升级到：`Wind` 或 `iFinD / Choice`
- 美股主源升级到：`Polygon`
- 新闻升级到：企业级财经新闻源 + 官方公告回查

## 二、按资源类别给建议

## 1. A股行情与基本面

### 推荐顺序

1. `Wind`
2. `同花顺 iFinD`
3. `Choice`
4. `Tushare Pro`
5. `AkShare`

### 建议定位

- `Wind / iFinD / Choice`：正式高可信主源
- `Tushare Pro`：高性价比主源 / 正式备用源
- `AkShare`：开发辅助源 / 备用源

### 具体可选来源

#### A. Wind

- 官方产品页：`https://www.wind.com.cn/portal/zh/WFT/index.html`
- 下载中心：`https://www.wind.com.cn/windftp/download.htm`
- API / 数据接入合作：`https://share.wind.com.cn/`

获取方式：

- 通过 Wind 商务或共享平台申请
- 机构版一般走商务采购，不是自助注册拿 key 的模式
- 开通后通常按终端、Client API 或定制接口交付

适合做什么：

- 机构级主数据源
- A股行情、财务、研报、事件、宏观的一体化供给

#### B. 同花顺 iFinD

- 官网 / 下载：`https://quantapi.51ifind.com/gwstatic/static/ds_web/quantapi-web/download.html`
- HTTP / SDK 手册：`https://quantapi.51ifind.com/gwstatic/static/ds_web/quantapi-web/help-center/manual.html`
- 权限说明：`https://quantapi.51ifind.com/gwstatic/static/ds_web/quantapi-web/help-center/permission.html`

获取方式：

- 注册 iFinD 账号
- 正式采购或申请试用
- 按需选择 HTTP API 或 SDK
- 获取账号后登录，再申请 / 刷新 access token

适合做什么：

- A股高性价比正式主源
- 适合量化研究和平台化数据调用

#### C. Choice

- 官网：`https://www.choice-china.com/index.html`
- 使用说明：`https://www.choice-china.com/guide.html`
- Python API 手册：`https://quantapi.eastmoney.com/Upload/EMQuantAPI_Python.pdf`

获取方式：

- 官网申请试用或商务采购
- 在开发者中心创建应用
- 获取 AppKey 或相应 API 权限

适合做什么：

- A股与宏观、行业、资讯一体化接入
- 适合作为 Wind 之外的正式替代方案

#### D. Tushare Pro

- 文档入口：`https://www.tushare.pro/document/search`
- 账户/积分说明示例：`https://tushare.pro/document/1?doc_id=307`

获取方式：

- 注册 Tushare Pro 账号
- 获取 token
- 通过积分体系开通更高权限接口

适合做什么：

- 高性价比主源或备用源
- 更适合平台后台批量拉取和补数

#### E. AkShare

- 官方文档：`https://akshare.akfamily.xyz/`
- GitHub：`https://github.com/akfamily/akshare`

获取方式：

- 直接安装 Python 包
- 无独立账号体系，具体可用性取决于上游站点和接口状态

适合做什么：

- 备用源
- 开发验证
- 补数和快速试验

### 官方回查必接

- 上交所
- 深交所
- 巨潮资讯

获取方式：

- 巨潮资讯：`https://www.cninfo.com.cn/`
- 上交所：`https://www.sse.com.cn/`
- 深交所：`https://www.szse.cn/`
- 优先保存公告原文链接、发布时间、证券代码、公告标题

### 我当前建议

- 如果内部 ClickHouse 数据仓库长期稳定可维护：
  - 平台优先读内部 ClickHouse
  - `Tushare Pro + AkShare + 交易所公告回查` 用作补数与交叉校验
- 如果内部仓库还不稳定：
  - 现在先用 `Tushare Pro + AkShare + 交易所公告回查`
- 后面预算允许：升级 `Wind` 优先

## 2. 美股行情、财务与公告

### 推荐顺序

1. `Polygon`
2. `Alpaca`
3. `SEC EDGAR`
4. `FRED / ALFRED`

### 建议定位

- `Polygon`：正式高质量行情主源
- `Alpaca`：高性价比开发/研究/纸面交易主源
- `SEC EDGAR`：公告/财务真值源，必接
- `FRED / ALFRED`：宏观真值源，必接

### 具体可选来源

#### A. Polygon

- 官网：`https://polygon.io/`
- 文档：`https://polygon.io/docs`
- 定价：`https://polygon.io/pricing`

获取方式：

- 官网注册
- 创建 API Key
- 根据所需资产类别和实时/延迟权限选择套餐

适合做什么：

- 美股正式行情主源
- 历史 K 线、公司行为、参考数据、新闻扩展

#### B. Alpaca

- 文档：`https://docs.alpaca.markets/`
- 数据与交易入口：`https://alpaca.markets/algorithmic-traders`
- Python 纸面交易示例：`https://alpaca.markets/sdks/python/trading.html`

获取方式：

- 注册 Alpaca 账号
- 先开 `Paper Only Account`
- 在控制台生成 API Key / Secret

适合做什么：

- 美股高性价比研究源
- 纸面交易和执行链路验证

#### C. SEC EDGAR

- API 文档：`https://www.sec.gov/edgar/sec-api-documentation`
- 开发者入口：`https://www.sec.gov/about/developer-resources`

获取方式：

- 无需 API Key
- 直接按官方文档调用 `data.sec.gov`
- 大批量场景优先用官方 bulk zip

适合做什么：

- 公告与财务真值层
- 给新闻核验和财务事实回查用

#### D. FRED / ALFRED

- API 文档：`https://fred.stlouisfed.org/docs/api/fred`
- API Key 说明：`https://fred.stlouisfed.org/docs/api/fred/v2/api_key.html`

获取方式：

- 注册 FRED 账号
- 申请 API Key
- 用 FRED/ALFRED 拉宏观现值与修订历史

适合做什么：

- 宏观真值层
- 给金融助手和研究报告补宏观序列

### 我当前建议

- 现在：`Alpaca + SEC EDGAR + FRED`
- 后面升级：`Polygon + SEC EDGAR + FRED`

## 3. 加密货币行情

1. `Binance 官方 API`
2. 第二家主流交易所官方 API

### 建议定位

- 交易所官方 API：主源和备用源
- 第三方聚合服务：可做补充，不建议做唯一真值源

### 具体可选来源

#### A. Binance 官方 API

- 开发者入口：`https://developers.binance.com/`
- 现货/通用文档：`https://developers.binance.com/docs/binance-spot-api-docs`

获取方式：

- 注册 Binance 账号
- 在 API 管理页创建 API Key
- 对只读行情场景，优先只开读取权限，不开交易权限

适合做什么：

- 加密现货主源

- 现在：`Binance 官方 API`

## 4. 新闻、资讯与外部信息

### 推荐顺序

1. `官方公告 / 监管披露 / 交易所公告`
2. `企业级财经新闻源`
3. `NewsAPI` 这类聚合器

### 建议定位

- 官方公告源：事实真值层
- 企业级财经新闻源：正式新闻主源
- 聚合器：线索发现层，不是最终真值层

### 具体可选来源

#### A. 官方公告 / 监管披露

- A股
  - 巨潮资讯网：`https://www.cninfo.com.cn/`
  - 上交所公告：`https://www.sse.com.cn/`
  - 深交所公告：`https://www.szse.cn/`
- 美股
  - SEC EDGAR：`https://www.sec.gov/edgar/sec-api-documentation`
- 宏观
  - FRED / ALFRED：`https://fred.stlouisfed.org/`

获取方式：

- 官方网站直接检索公告
- 如果资源部门能提供结构化抓取或镜像，同步进平台内部数据中心
- A股公告优先落 PDF 原文、公告标题、发布时间、证券代码、公告类型
- 美股公告优先落 filing 元数据、原文链接、提交时间、表单类型

适合做什么：

- 给导师/助手提供“最终引用依据”
- 给新闻分析做原文核验
- 给回测和复盘补公司事件证据

#### B. 企业级财经新闻源

- Polygon News：`https://polygon.io/docs/rest/quickstart`、`https://polygon.io/blog/new-and-improved-financial-news-api/`
- Polygon + Benzinga：`https://polygon.io/partners/benzinga`
- marketaux：`https://www.marketaux.com/pricing`、`https://www.marketaux.com/documentation`

获取方式：

- Polygon
  - 注册 Polygon 账号
  - 在控制台创建 API Key
  - 如果要用 Benzinga 新闻，需要在 Polygon 账户里额外加对应 expansion
- marketaux
  - 官网注册
  - 直接获取 `api_token`
  - 适合先低成本接入和原型验证

适合做什么：

- 做平台正式新闻主源
- 提供结构化新闻元数据：标题、发布时间、来源、URL、ticker、标签
- 给金融助手做“线索 -> 原文 -> 结论”链路

#### C. 聚合器

- NewsAPI：`https://newsapi.org/register`、`https://newsapi.org/docs/authentication`

获取方式：

- 官网注册
- 获取 API Key
- 用关键词、媒体源、时间窗口做基础聚合检索

适合做什么：

- 发现新闻线索
- 扩大监控覆盖面
- 不适合直接作为最终真值层

### 我当前建议

- 最低成本起步：
  - A股/美股公告先接 `巨潮资讯 + 上交所/深交所 + SEC EDGAR`
  - 新闻补充先接 `marketaux` 或 `NewsAPI`
- 更稳的正式方案：
  - 官方公告做真值层
  - `Polygon News` 或 `Polygon + Benzinga` 做正式新闻主源
- 平台内部规则：
  - 新闻只能先入平台数据中心，再给用户用
  - 最终展示必须带原文 URL、发布时间、来源名
  - 聚合器结果必须再做官方原文回查

## 5. OCR / 交割单识别

### 推荐顺序

1. `商业 OCR 服务`
2. `自建 OCR 模型`

### 建议定位

- 商业 OCR：先上线最稳
- 自建模型：后续在有样本库后再做

### 必要条件

- 多券商样本
- 截图样本
- 人工确认流

### 具体可选来源

#### A. 腾讯云 OCR

- 官网：`https://intl.cloud.tencent.com/products/ocr`
- 计费说明：`https://intl.cloud.tencent.com/document/product/1005/36165`
- 同步请求示例：`https://intl.cloud.tencent.com/document/product/1045/73116`

获取方式：

- 注册腾讯云账号
- 开通 OCR 服务
- 创建密钥
- 直接走 API / SDK 调用

适合做什么：

- 中文截图识别
- 国内服务接入
- 先做交割单截图、账单截图、通用印刷体识别

#### B. Google Cloud Vision OCR

- OCR 文档：`https://cloud.google.com/vision/docs/ocr`
- Quickstart：`https://cloud.google.com/vision/docs/quickstarts`

获取方式：

- 注册 Google Cloud
- 创建项目并启用 Vision API
- 配置服务账号或 Application Default Credentials
- 通过 REST 或官方 SDK 调用 `TEXT_DETECTION / DOCUMENT_TEXT_DETECTION`

适合做什么：

- 通用文本 OCR
- 多语言截图识别
- 海外云环境部署

#### C. Azure Document Intelligence

- 产品概览：`https://learn.microsoft.com/en-us/azure/ai-services/document-intelligence/overview`
- 定价页：`https://azure.microsoft.com/zh-cn/pricing/details/ai-document-intelligence/`

获取方式：

- 注册 Azure
- 创建 Document Intelligence 资源
- 获取 endpoint 和 key
- 用预构建模型或通用读取模型处理图片/PDF

适合做什么：

- 文档结构化抽取
- 表格、表单、票据型识别
- 如果以后要识别更复杂账单，优先级高于纯通用 OCR

#### D. Amazon Textract

- 产品说明：`https://docs.aws.amazon.com/textract/latest/dg/what-is.html`
- 定价页：`https://aws.amazon.com/textract/pricing/`

获取方式：

- 注册 AWS
- 开通 Textract
- 配置 IAM 权限
- 调用 `DetectDocumentText` 或 `AnalyzeDocument`

适合做什么：

- PDF / 表单 / 表格结构化识别
- 海外账单或复杂报表识别

### 我当前建议

- 如果优先考虑中文环境和接入速度：
  - 先接 `腾讯云 OCR`
- 如果优先考虑多语言和海外兼容：
  - 先接 `Google Cloud Vision OCR`
- 如果重点是复杂账单、表格和结构化字段抽取：
  - 优先评估 `Azure Document Intelligence` 或 `Amazon Textract`
- 平台落地规则：
  - OCR 只负责“识别候选结果”
  - 所有 OCR 结果必须人工确认后入库
  - 要保留原图、识别结果、人工修正记录

  - 深交所：`https://www.szse.cn/`

## 7. 历史真值样本

### 推荐顺序

1. `内部真实样本`
2. `脱敏样本库`

### 建议定位

- 真实样本：回测/OCR/导师正确性基线
- 脱敏样本：开发与测试补充

### 获取方式

- 交割单样本
  - 由内部交易团队、运营团队、测试团队提供脱敏导出
- 成交截图样本
  - 由真实用户或内部同事提供，统一脱敏后入库
- 回测基准样本
  - 由研究员选定一批简单、已知结果可复现的基准策略
- 导师问答真值样本
  - 由研究团队整理“问题-标准答案-引用来源”

适合做什么：

- OCR 训练与验收
- 回测回归测试
- 导师/助手正确性评估

### 我当前建议

- 至少准备：
  - 真实交割单样本
  - 成交截图样本
  - 回测基准样本
  - 已知事件与市场反应样本
  - 已知正确答案的导师问答样本

- 美股纸面执行验证
- 订单状态、持仓、撤单链路联调

#### B. SimNow

- 官网：`https://www.simnow.com.cn/`
- 产品页：`https://www.simnow.com.cn/product.action`

获取方式：

## 9. 基础设施

### 必选

- `PostgreSQL`
- `MinIO / S3`
- `Redis`

### 可选增强

- 独立日志系统
- 监控与报警
- 备份和归档

### 具体建议

- PostgreSQL
  - 用于业务库、任务、用户、审计、研究结果
- MinIO / S3
  - 用于原始响应、截图、OCR 中间结果、快照归档
- Redis
  - 用于缓存、队列、短期会话状态
- 可选增强
  - Prometheus + Grafana：监控
  - Loki / ELK：日志检索
  - 定时备份任务：数据库和对象存储归档

### 我当前建议

- 现阶段继续用你已提供的 `PostgreSQL + Redis + MinIO`

## 10. 统一数据接入层

### 推荐顺序

1. `自建统一数据网关`
2. `参考 OpenBB provider 架构`

### 获取方式

- 不采购成品，平台自己实现
- 外部数据源只作为 provider 接进来
- 内部统一输出标准对象：行情、公告、新闻、规则、快照、引用

### 技术建议

- 后端继续用现有 Python 服务层实现 provider 抽象
- 每个 provider 统一输出：
  - 来源名
  - 请求参数
  - 原始时间
  - 快照 ID
  - 引用链接

适合做什么：

- 防止页面直接耦合外部接口
- 为回测、复盘、导师、助手提供统一证据层

### 必须做到

- provider 标记
- 请求参数记录
- 数据快照 ID
- 响应摘要 hash
- 双源冲突标记

### 我当前建议

- 不直接把数据源裸接到导师/助手
- 先做统一数据证据层

## 11. LLM / 推理服务
