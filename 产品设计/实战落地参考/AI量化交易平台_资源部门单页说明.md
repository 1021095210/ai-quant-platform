# AI量化交易平台资源部门单页说明

> 给资源提供部门看的简版说明

## 1. 我们要做什么

我们在做一个金融量化研究平台。  
这个平台需要稳定、可追溯的数据，给用户做：

- 行情查看
- 回测
- 交易复盘
- 新闻/公告分析
- AI 辅助研究

## 2. 我们需要什么资源

### 必需资源

- A股行情数据
- 美股行情数据
- 加密行情数据
- 新闻/公告数据
- 市场规则资料
- 基础设施：
  - PostgreSQL
  - MinIO / 对象存储
  - Redis

### 强烈建议资源

- 双源校验数据
- 历史真值样本
- OCR 识别能力
- 券商沙盒或模拟交易接口
- 稳定 LLM API

## 3. 为什么需要这些资源

- 平台不能只靠网页抓取或临时接口
- 金融数据必须可追溯、可复现
- 回测必须绑定固定数据快照
- 新闻和公告必须能回查来源
- AI 只能基于证据回答，不能自己编

## 4. 这些资源怎么用

不是每个用户都去请求第三方接口。  
正确方式是：

1. 平台后台统一拉取上游数据
2. 平台内部保存原始数据和标准化数据
3. 平台按市场和时间做增量更新
4. 用户查询时只读平台内部数据

这样做的原因：

- 更快
- 更稳定
- 不容易被限流
- 成本更低
- 数据口径统一
- 结果可复现

## 5. 资源提供部门需要重点确认什么

- 能不能长期稳定提供
- 能不能批量获取
- 能不能增量更新
- 能不能说明来源和时间
- 能不能允许平台内部保存和使用
- 有没有调用限制、授权限制、商业使用限制

## 6. 我们当前推荐的起步方案

- A股：Tushare Pro + AkShare + 交易所公告回查
- 美股：Alpaca + SEC EDGAR + FRED
- 加密：Binance 官方 API
- 新闻：官方公告优先，聚合新闻补充
- 基础设施：PostgreSQL + MinIO + Redis

如果内部已经有稳定数据仓库：

- 平台优先读取内部数据仓库
- 第三方接口只用于补数、校验和增量更新

## 7. 一句话结论

我们需要的不是“给用户一个查数据接口”，而是“给平台一套可长期拉取、保存、更新、校验的数据资源体系”。
