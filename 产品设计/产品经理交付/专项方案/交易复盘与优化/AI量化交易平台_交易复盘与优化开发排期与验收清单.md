# AI量化交易平台交易复盘与优化开发排期与验收清单

## 1. 目的

这份文档用于把《交易复盘与优化研发拆解》继续收敛为：

- 开发排期
- 任务优先级
- 分阶段交付目标
- 研发 / 测试验收清单

适用对象：

- 项目负责人
- 开发
- 测试
- 产品

## 2. 排期原则

### 原则一：先打通主链路，再做增强

优先让用户完成：

1. 上传成交记录
2. 获取可信复盘结果
3. 看懂核心结论
4. 拿到可执行优化建议

### 原则二：先做 A 股主链路

当前优先基于内部 ClickHouse 做 A 股日线和分钟级复盘，不先发散到多市场。

### 原则三：先做可解释结果，再做复杂自动化

先保证：

- 结论可信
- 结果可对照
- 来源可追溯

再做更强的自动规则回写和更复杂的优化搜索。

## 3. 分阶段开发排期

## Phase 1：主链路打通

### 目标

让用户可以完成从成交上传到基础复盘结果查看的闭环。

### 范围

- 统一交易记录结构
- CSV / 手动录入 / 长文字三条主输入链路稳定
- A 股内部 ClickHouse 补价
- 精简结论
- 亏损特征 Top 5
- 默认夏普最大目标版本
- 目标版本收益曲线
- 目标版本成交记录

### 优先级

- `P0`

### 验收标准

- 用户成功上传成交记录后可进入统一复盘流程
- 所有自动补价都能标注来源
- 页面能展示精简结论
- 页面能展示亏损特征 Top 5
- 默认选中夏普最大
- 默认能看到收益曲线和 5-10 笔成交记录

## Phase 2：分析层增强

### 目标

让复盘从“基础结果展示”升级成“可比较、可解释、可选择优化目标”的分析工具。

### 范围

- 盈利特征列表
- 胜率 / 回撤 / 收益 / 夏普 四类目标版本
- 旧新参数对比
- 指标条件替换
- 收益曲线叠加勾选
- 分钟级微观特征复盘
- 市场环境自动 / 手动触发

### 优先级

- `P1`

### 验收标准

- 用户能切换四类目标版本
- 盈利特征默认放在亏损特征之后，并支持折叠
- 能对比旧参数和新参数
- 能看懂规则替换建议
- 可切换或叠加收益曲线
- 分钟级特征能输出明确结论

## Phase 3：深度优化与商业化预留

### 目标

让模块具备更强参数优化能力和后续收费能力。

### 范围

- 基本面因子全量勾选分组
- 综合评分排序
- OCR 第一阶段结果接入复盘主链路
- 免费 / 会员额度识别
- 超额后的限制与付费预留
- 管理员 / 内部测试账号的规则回写入口预留

### 优先级

- `P2`

### 验收标准

- 用户能选择不同排序逻辑
- 基本面开关生效且结果可解释
- OCR 识别结果能进入统一复盘
- 免费 / 会员额度能正确识别
- 超额逻辑能正确阻止或提示

## 4. 任务优先级清单

### P0 任务

1. 定义统一交易记录结构
2. 打通 A 股内部 ClickHouse 补价
3. 实现复盘任务主接口
4. 实现精简结论区
5. 实现亏损特征 Top 5
6. 实现夏普最大默认版本
7. 实现收益曲线卡
8. 实现成交记录卡

### P1 任务

1. 实现盈利特征区
2. 实现四类目标版本切换
3. 实现旧新参数对比
4. 实现指标条件替换
5. 实现曲线叠加对比
6. 实现分钟级特征提取
7. 实现市场环境复盘

### P2 任务

1. 实现基本面分组勾选
2. 实现综合评分排序
3. 接入 OCR 结果进入统一复盘
4. 实现额度识别
5. 实现按次 / 超额预留
6. 预留规则回写入口

## 5. 页面开发顺序

### 先做

- 结果页主框架
- 精简结论
- 亏损特征
- 夏普最大默认版本

### 再做

- 盈利特征
- 多目标切换
- 参数对比
- 条件替换

### 最后做

- 曲线叠加
- 基本面复盘勾选
- 计费与额度提示

## 6. 接口开发顺序

### 第一批接口

1. 成交记录标准化预览
2. 发起复盘任务
3. 获取复盘摘要
4. 获取目标版本详情

### 第二批接口

1. 获取参数对比
2. 获取条件替换
3. 获取分钟级复盘详情
4. 获取市场环境复盘详情

### 第三批接口

1. 获取额度信息
2. 获取基本面复盘详情
3. 获取内部规则回写建议

## 8. 每阶段交付给产品验收的东西

### Phase 1

- 页面可点击原型落成
- 主链路结果可展示
- 基础体验可走通

### Phase 2

- 多版本比较可用
- 复盘解释力明显增强
- 用户可做明确优化取舍

### Phase 3

- 分析深度增强
- 商业化边界明确
- 内部高级测试入口预留

## 9. 风险与注意事项

### 风险一：过拟合

- 指标不设上限，但必须提示推荐指标数量
- 不能让系统输出看似漂亮但逻辑混乱的结果

### 风险二：数据口径不一致

- 日级与分钟级必须明确分口径
- 所有补价、补指标都必须可追溯来源

### 风险三：结果过度复杂

- 默认先给精简结论
- 高级结果放在后续层级展开

### 风险四：商业化边界提前写死

- 当前只做免费 / 会员 / 超额预留
- 不先把额度数值完全锁死

## 10. 当前建议的实际起手顺序

如果研发现在就开始做，我建议按下面顺序起手：

1. 统一交易记录结构
2. 打通内部 ClickHouse A 股补价
3. 先实现精简结论 + 亏损特征 Top 5
4. 再做夏普最大默认版本
5. 再做收益曲线 + 成交记录
6. 最后逐步补四目标版本和参数替换
