# AI量化交易平台 PRD v1.0

## 1. 文档目标

本 PRD 用于明确 AI量化交易平台当前版本和下一阶段的产品范围、核心流程、功能优先级、验收口径和依赖资源，作为公司内部评审和后续研发推进依据。

## 2. 产品定位

### 产品定义

一套面向外部真实用户的 AI 研究、回测与复盘平台，帮助不同经验层级的交易者在一个平台内完成学习、研究、验证和复盘。

### 入口原则

- 首页负责吸引和分流
- 工作台负责登录后的统一中枢
- 金融导师负责新手教学、平台使用指导和量化入门引导

### 产品边界

本产品当前优先解决：

- 不会写代码也能做策略研究
- 学习、研究、回测、复盘之间缺少统一闭环
- 真实成交复盘难以沉淀成可复用优化规则
- 回测与研究结果的可信度不足

本产品当前不优先解决：

- 自动交易执行
- 全市场实盘化
- 社区化内容平台
- 高并发实时行情终端

## 3. 目标用户与角色

### 用户角色

1. 新手股民用户
- 交易经验有限
- 不懂量化
- 更需要教学、解释和平台使用引导

2. 有交易经验但不会编程的个人交易者
- 已有交易方法
- 想把主观经验转成可验证规则
- 需要低门槛研究工具

3. 有一定研究能力的高级用户
- 有一定交易框架和研究习惯
- 更关注策略研究、信息整合、执行效率和分析深度

4. 管理员
- 负责查看用户情况、任务状态、报错日志、平台治理信息

## 4. 核心用户目标

### 新手股民目标

- 学会平台怎么用
- 理解基础交易概念和技术指标
- 从“看不懂量化”进入“能开始研究”

### 有交易经验但不会编程的个人交易者目标

- 快速理解平台怎么用
- 快速研究一套交易想法
- 快速复盘自己的历史交易

### 高级用户目标

- 把交易想法转成可验证策略
- 用可信数据做回测与比较
- 把复盘结论沉淀成下一轮规则调整
- 借助金融助手节省信息获取和分析时间

### 管理员目标

- 看到平台运行情况
- 看到用户使用问题和错误日志
- 具备基础运营和治理视图

## 5. 核心流程

### MVP 第一主路径

1. 用户先通过金融导师理解平台和基础交易概念
2. 进入策略工坊生成第一版策略
3. 进入回测中心验证策略
4. 进入交易复盘分析真实历史交易
5. 返回工作台继续下一轮研究

### 流程一：策略研究

1. 登录进入工作台
2. 在策略工坊输入策略想法
3. 生成结构化策略和 Python 样例
4. 保存策略项目与版本
5. 跳转回测中心运行回测
6. 查看回测结果、配置摘要、执行约束和对比结果

### 流程二：交易复盘

1. 登录进入交易复盘
2. 选择 CSV、截图或手动录入
3. 解析成交记录
4. 运行 AI 复盘
5. 查看复盘总结与优化建议
6. 将结论带回策略工坊继续验证

### 流程三：新手学习

1. 登录进入平台
2. 进入金融导师
3. 询问金融基础、技术指标、量化概念和平台使用问题
4. 获得解释、下一步动作和模块入口

## 6. 当前核心模块

### 6.1 首页

目标：

- 作为平台入口
- 建立平台定位和用户第一印象

### 6.2 用户工作台

目标：

- 成为研究中枢
- 汇总最近项目、回测、复盘、任务和数据状态

### 6.3 管理员后台

目标：

- 提供平台概览、用户管理、日志和治理视图

### 6.4 策略工坊

目标：

- 用自然语言生成策略
- 管理策略名称、版本标签和保存状态

### 6.5 回测中心

目标：

- 运行回测
- 展示回测结果
- 展示数据来源、执行约束和配置摘要
- 支持回测对比

### 6.6 交易复盘

目标：

- 解析真实交易记录
- 自动补价和智能识别
- 输出优化建议
- 作为平台当前第一差异化能力

### 6.7 指标设置与规则模块

目标：

- 管理内置指标、自定义指标和默认研究规则

### 6.8 金融导师 / 金融助手

目标：

- 金融导师：偏教学，帮助纯新股民和小白用户理解金融基础、交易概念、技术指标、量化入门和平台使用
- 金融助手：偏研究执行，帮助高级用户更快获取信息、组织研究和形成分析结果
- 后续都逐步演进为带证据链的辅助系统

## 7. 功能优先级

### P0：必须持续补硬

- 内部数据中心真实接入
- 回测执行约束补硬
- 数据快照与证据链
- 登录、用户隔离、管理员后台稳定性

### P1：强实用性模块

- 工作台研究中枢
- 交易复盘自动化增强
- 导师/助手引用式回答
- 模块间下一步引导

### 当前 MVP 范围说明

当前 MVP 不删除现有主要模块，而是保留当前核心闭环能力，并以“导师 -> 策略 -> 回测 -> 复盘”作为第一主路径。

### P2：增强能力

- 更多市场支持
- 更复杂 OCR
- 更丰富策略模板
- 更多实验与研究工具

## 8. 当前验收标准

### 产品层

- 用户能完成策略研究主流程
- 用户能完成复盘主流程
- 新手能通过导师理解平台和基础交易知识
- 管理员能查看平台基本运营状态

### 商业验证层

- 能观测用户是否愿意在 7 天内持续回访
- 能观测用户更偏好哪个模块
- 能验证真实用户是否认为平台“对交易研究有帮助”

### 可信度层

- 回测结果明确展示数据来源
- 回测结果明确展示执行约束
- 内部数据中心优先作为主链路
- 重要结论不能脱离来源和上下文

### 工程层

- 核心页面能打开
- 登录和权限链路正常
- 自动化测试通过
- 接力文档和模块文档保持同步

## 9. 关键依赖

- 内部 ClickHouse 数据仓库
- PostgreSQL / Redis / MinIO
- 正式新闻源
- OCR 服务
- LLM API
- 真实样本库

## 10. 风险与限制

### 当前风险

- 多市场能力展示已较强，但真实主链路仍以 A股为主
- 外部信息和导师回答还未完全建立引用式证据层
- 正式部署和长期外部可访问形态仍未定版

### 当前限制

- 平台仍然是研究与复盘平台，不是自动交易平台
- 当前不能承诺所有市场和所有结论“绝对正确”
- 金融级可信度依赖数据源、规则源和样本库持续补齐

## 11. 当前差异化定位

### 第一差异点

- 真实成交复盘能力

### 第二差异点

- 金融导师 + 金融助手双角色体系

### 平台级差异

- 把学习、研究、回测、复盘放进一个可联动的平台，而不是分散成多个独立工具

## 12. 当前阶段成功指标

### 主指标

- 用户 7 日留存

### 当前阶段最重要的业务判断

- 用户是否真的持续回来使用平台

### 辅助指标

- 完成一次研究闭环的用户数
- 交易复盘使用次数
- 金融导师使用人数
- 金融助手使用人数
- 用户主观反馈“是否真的有帮助”

## 13. 当前商业模式设计

### 当前阶段

- 先不收费，以验证产品价值和用户持续使用意愿为主

### 预留商业化方向

- 免费版 / 会员版
- 部分高级功能按次付费
- 成交复盘按次收费
- 金融助手按 token 或高级额度收费
- 后续企业版 / 团队版

### 当前建议的额度思路

- 免费版：
  - 保留全部核心功能入口
  - 不同用户可按自身需求选择进入不同模块
  - 关键模块都提供基础体验次数或额度，让用户先感知价值
  - 成交复盘按月限制在体验级额度，当前建议 `3-5 次 / 月`
  - 金融助手按 token 额度设计，先保证能体验 `1-2 次` 完整高质量研究流程，具体数值后续根据真实成本与效果测试决定
- 会员版：
  - 提升复盘次数和金融助手 token 额度
  - 如果会员额度超上限，再单独购买额外额度
  - 不直接定义为无限，避免前期成本不可控
- 免费版超出额度：
  - 可以升级会员
  - 也可以单独购买额外额度
- 企业版：
  - 保留为未来方向
  - 不纳入当前 MVP 范围

### 当前收费结构结论

- 金融助手：按 `token 额度` 计量
- 成交复盘：会员内含次数，超额按次
- 会员版最核心的付费理由：`更多次数 / 更高额度`

## 11. 下一阶段产品目标

1. 继续补硬可信数据和回测链路
2. 优先深化交易复盘能力
3. 把导师和助手从“能聊”升级到“有证据的研究辅助”
4. 形成对公司可持续汇报、可持续申请资源的产品基线
