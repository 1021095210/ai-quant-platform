# AI量化交易平台全平台开发排期与验收清单

## 1. 目的

这份文档用于从全平台视角明确：

- 下一阶段先做什么
- 每个阶段包含哪些模块
- 做到什么算完成
- 产品、开发、测试如何共同验收

## 2. 排期原则

### 原则一：先做高价值闭环

优先围绕：

- 学习
- 研究
- 回测
- 复盘

形成能真正帮用户留下来的闭环。

### 原则二：先做可信，再做更广

优先保证：

- 数据可信
- 回测可信
- 复盘可信

再去扩更多市场和更多玩法。

### 原则三：先做 A 股实用版本

当前短期优先深耕：

- A 股

## 3. 阶段排期

## Phase 1：可信研究主链路

### 目标

让平台形成一个可用、可信、可解释的 A 股研究主链路。

### 范围

- 平台数据中心
- 策略工坊
- 回测中心
- 交易复盘与优化
- 用户工作台

### 验收标准

- 用户可以完成一条完整研究链路
- 回测和复盘都绑定真实数据来源
- 工作台可承接研究过程

## Phase 2：体验增强与双角色完善

### 目标

让不同经验层级用户都更容易持续使用。

### 范围

- 首页
- 金融导师
- 金融助手
- 登录 / 注册 / 账户
- 管理员工作台

### 验收标准

- 新手能被正确引导
- 高级用户能获得更强研究辅助
- 管理员能更好管理用户和问题

## Phase 3：商业化与治理完善

### 目标

为后续收费和平台治理提供基础。

### 范围

- 额度与会员体系
- 日志与运营能力
- 企业版预留能力
- 高级规则回写与内部测试能力

### 验收标准

- 免费 / 会员边界明确
- 平台异常可观测
- 企业版方向具备继续推进基础

## 4. 模块优先级矩阵

| 模块 | 当前阶段 | 优先级 | 当前主要目标 |
|------|----------|--------|--------------|
| 平台数据中心 | Phase 1 | P0 | 打通内部数据真实链路 |
| 回测中心 | Phase 1 | P0 | 继续补硬可信度 |
| 交易复盘与优化 | Phase 1 | P0 | 做成平台最强差异化模块 |
| 用户工作台 | Phase 1 | P0 | 做成真正的研究中枢 |
| 策略工坊 | Phase 1 | P1 | 强化模板、版本和联动 |
| 首页 | Phase 2 | P1 | 稳定承接流量和分流 |
| 金融导师 | Phase 2 | P1 | 做强教学和新手引导 |
| 金融助手 | Phase 2 | P1 | 做强研究执行和信息整合 |
| 管理员工作台 | Phase 2 | P1 | 加强治理和运营 |
| 登录 / 注册 / 账户 | Phase 2 | P1 | 对接会员和额度体系 |
| 指标设置 | Phase 3 | P2 | 完善指标库和管理能力 |
| 规则模块 | Phase 3 | P2 | 完善规则模板与用户层 |
| 日志与运营能力 | Phase 3 | P1 | 提升平台治理能力 |

## 5. 当前建议起手顺序

1. 平台数据中心
2. 回测中心
3. 交易复盘与优化
4. 用户工作台
5. 金融导师 / 金融助手

## 6. 测试验收结构

### 产品验收

- 核心路径是否清楚
- 页面是否符合用户习惯
- 模块价值是否能被感知

### 开发验收

- 接口是否稳定
- 数据链路是否可追溯
- 模块联动是否正常

### 测试验收

- 主链路是否覆盖
- 异常情况是否覆盖
- 关键文档是否同步

## 7. 当前给公司的建议

- 平台已经具备较完整模块，不建议继续广撒网扩功能
- 当前最值得投入的是：
  - 数据可信
  - 回测可信
  - 交易复盘与优化
  - 工作台中枢化
- 如果继续投入，这几块最容易产出真实用户价值和后续付费意愿
