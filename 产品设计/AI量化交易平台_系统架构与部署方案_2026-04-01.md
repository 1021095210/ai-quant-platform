# AI 量化交易平台系统架构与部署方案

## 一、设计阶段最核心的技术回答

### 1. 前端用什么

当前前端使用 `纯 HTML + Vanilla JavaScript + CSS`，由 `FastAPI` 直接托管，不是 React、Vue、Streamlit，也不是“不需要前端”。这是基于当前阶段要优先保证研究流程可运行、部署简单、Agent 易接力的现实选择。

### 2. 后端用什么

后端使用 `Python 3.11 + FastAPI + Uvicorn`。应用层通过 `SQLAlchemy` 持久化业务对象，当前长任务仍在应用进程内执行，后续再演进为独立 worker。

### 3. 数据存哪里

- 业务元数据与结果：
  - 本地开发默认 `SQLite`
  - 共享/部署环境建议 `PostgreSQL`
- 行情缓存与市场数据快照摘要：
  - 独立 `SQLite` 文件，放在持久卷
- 缓存 / 队列基线：
  - `Redis`
- 对象存储基线：
  - `MinIO`

### 4. 有没有 AI 组件

有，但当前真实运行链路里仍以规则模板和结构化生成逻辑为主。配置层已经预留 `OpenAI 兼容 API`，主要用于三类任务：

- 自然语言策略描述转结构化 DSL
- 交易复盘总结
- 工作台研究摘要

当前平台仍坚持白名单字段输出，不把原始交割单全文直接发送给外部模型。

### 5. 怎么部署

当前采用 `Docker` 作为统一运行载体，并通过 `Docker Compose` 管理多服务编排，分两种部署模式：

- 本地一体化：`infra/docker-compose.yml`
- 外部托管依赖：`infra/docker-compose.external.yml`

也保留本地直跑 FastAPI 的轻量演示模式，适合开发期快速试用。

## 二、系统分层

### 1. 展示层

- 首页
- 登录 / 注册
- 用户工作台
- 策略工坊
- 回测中心
- 交易复盘
- 指标设置
- 规则模块

### 2. 应用层

- 认证服务
- 策略生成服务
- 回测任务服务
- 复盘任务服务
- 指标服务
- 规则服务
- 工作台汇总服务

### 3. 数据层

- 业务数据库：用户、项目、任务、上传记录、规则、指标
- 市场缓存数据库：行情、同步范围、快照摘要相关数据
- Redis：后续任务队列和短期状态
- MinIO：后续对象文件与导出文件

## 三、数据流转

### 1. 策略生成数据流

用户输入自然语言描述 -> 后端解析市场、周期、术语和混合周期上下文 -> 生成结构化 DSL、Python 样例、歧义提示和摘要 -> 用户保存为策略项目版本 -> 项目版本写入业务数据库

### 2. 回测数据流

用户选择策略版本并填写回测配置 -> 后端标准化 `execution_contract` -> 生成 `config_revision` -> 绑定 `data_snapshot_ref` -> 生成或读取 `data_snapshot_summary` -> 回测引擎读取策略 DSL 和数据快照 -> 输出收益、回撤、交易明细、仓位和风控摘要 -> 结果写回任务表 -> 工作台与回测中心读取结果

### 3. 交易复盘数据流

用户上传交割单 -> 后端接收文件和上传元数据 -> 解析成标准化交易记录 -> 聚合统计关键行为和结果 -> 生成复盘结论 -> 复盘任务结果写回业务数据库

### 4. 工作台汇总数据流

用户登录 -> 工作台请求当前用户汇总 -> 后端按 `user_id / workspace_id` 查询最近策略项目、回测、复盘、任务状态和快照摘要 -> 返回用户私有研究上下文

## 四、业务流转

### 1. 首次使用

打开首页 -> 进入登录/注册 -> 登录后进入用户工作台 -> 在策略工坊生成并保存第一个策略 -> 去回测中心发起回测 -> 查看回测结果和数据快照摘要

### 2. 日常研究

登录 -> 从工作台打开最近项目 -> 修改策略描述或规则 -> 再次发起回测 -> 比较最新结果 -> 根据复盘或回测结果继续迭代策略

### 3. 管理操作

管理员或开发者配置环境变量 -> 选择本地数据库或托管数据库 -> 校验 PostgreSQL / Redis / MinIO / 应用健康 -> 发布镜像 -> 启动容器 -> 观察 `/healthz` 与依赖校验结果

## 五、部署与运维

### 1. 本地一体化部署

适合开发和演示环境。使用 `infra/docker-compose.yml` 启动：

- API
- PostgreSQL
- Redis
- MinIO

这一模式解决的是“一个仓库拉起即可演示”的问题。

### 2. 外部托管依赖部署

适合已有数据库、缓存和对象存储的环境。使用 `infra/docker-compose.external.yml`，只启动 API 容器，把数据库、Redis、MinIO 指向外部托管服务。

### 3. 环境差异处理

- 开发环境：
  - SQLite 起步快
  - 适合功能联调
- 演示 / 共享环境：
  - PostgreSQL 更适合多用户和共享状态
  - Redis、MinIO 走独立服务
- 容器环境：
  - 所有差异统一收口到环境变量
  - `MARKET_DATA_DATABASE_PATH` 与业务数据库分离
  - 健康检查统一走 `/healthz`
