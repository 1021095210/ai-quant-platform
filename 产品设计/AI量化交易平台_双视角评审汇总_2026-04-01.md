# AI量化交易平台双视角评审汇总（2026-04-01）

本文汇总两份独立评审结果：

- `产品设计/AI量化交易平台_评审_交易员视角_2026-04-01.md`
- `产品设计/AI量化交易平台_评审_平台设计视角_2026-04-01.md`

目标不是推翻当前可运行版本，而是从“真实交易可用性”和“成熟 Web 平台设计”两个角度，筛出最值得进入下一阶段的优化事项。

## 一、交叉结论

两份评审虽然角度不同，但核心结论高度一致：

1. 当前平台已经有研究工作流雏形，但还不是严肃可追责的量化研究平台  
2. 最大短板不在“再多几个页面”，而在“回测执行假设、数据快照、风控仓位、实验可复现、工作台中枢化”  
3. 多市场和混合周期已经进入语义层，但执行层与结果展示层必须明确标示真实能力边界  
4. 首页应继续保持平台入口定位，真正的研究状态、运行状态和能力边界应集中到登录后的工作台与回测结果页

## 二、建议采纳的 P0 事项

以下建议同时被两份评审支持，且最适合作为下一阶段主线。

### 1. 回测配置对象化

把以下内容从“隐含默认值”升级为“明确可选、可落库、可展示”的回测配置：

- 成交方式
- 成交时点
- 复权模式
- 手续费
- 滑点
- 最小下单单位
- 市场约束
- T+1 / T+0

理由：

- 这是回测可信度的底线
- 也是多市场、多周期执行层的共同入口
- 可以直接写进 `config_revision`，与现有平台契约对齐

### 2. 数据快照透明化

强制把每次回测绑定到明确的 `data_snapshot_ref`，并在结果页展示：

- 数据源
- 覆盖范围
- 缺失率
- 最后更新时间
- 交易日历 / 时区
- warmup 规则

理由：

- 多市场场景下，数据透明度决定结果是否可信
- 这部分与当前已落地的 `dataset_snapshot_ref` 设计天然衔接

### 3. 最小风控与仓位模型

先落一套最小可用模型，不追求一次做全：

- 固定比例仓位或固定股数
- 最大持仓数
- 单票最大仓位
- 止损 / 止盈
- 最大回撤保护

理由：

- 没有风控和仓位，回测结果会系统性失真
- 这是从“演示级”走向“研究级”的关键一步

### 4. 工作台升级为研究中枢

工作台不再主要承担“模块入口”职责，而是集中展示：

- 最近项目
- 最近回测 / 实验
- 最近复盘
- 最近失败与待办
- 数据快照状态

理由：

- 首页已经收敛为平台入口
- 真正的研究动作应回到登录后的个人工作台

### 5. 平台语言与状态体系收敛

下一轮需要统一：

- 中英文混用
- 开发口吻文案
- 空状态 / 加载态 / 错误态
- 错误提示中的 `request_id`

理由：

- 这是成熟平台感的重要来源
- 也是后续扩展时最容易反复返工的部分

## 三、建议暂缓的事项

以下内容有价值，但不建议抢在当前主线前做：

- 真正多市场实时执行
- 券商 / 交易所直连
- 纸交易与实时告警闭环
- 组合级多资产回测
- Walk-forward / 样本外 / 蒙特卡洛
- 团队协作与权限中心

原因：

- 这些都建立在前述 P0 基础设施已经稳定的前提上
- 现在直接推进，平台会继续向“功能看起来很多，但底层不够硬”的方向偏移

## 四、给当前版本的执行建议

基于当前代码状态，建议下一阶段按这个顺序推进：

1. 回测配置对象化，并在结果页展示配置摘要  
2. 数据快照可见性增强，并把结果页/工作台都接入  
3. 最小风控与仓位模型接入回测配置  
4. 工作台改造成研究中枢  
5. 统一平台语言、空状态和错误态  

## 五、当前轮次结论

当前版本可以继续作为“现有版本”保留，不需要推倒重来。

下一轮优化不应以“新增页面”为目标，而应以“提升研究可信度、结果可复现性、工作流成熟度”为目标。
