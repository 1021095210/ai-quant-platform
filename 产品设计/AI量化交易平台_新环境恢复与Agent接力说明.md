## 四、新环境恢复步骤

如果你是新 Agent，请优先带用户执行以下步骤。

### 1. 检查关键目录

进入仓库后，先确认至少存在：

- `apps/`
- `infra/`
- `tests/`
- `tools/`
- `产品设计/`

### 2. 创建 Python 虚拟环境

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -U pip
pip install -e apps/api
```

说明：

- 当前测试和服务启动最好优先使用仓库内 `.venv`
- 如果系统 `python3` 缺依赖，优先用 `.venv/bin/python`

### 3. 准备环境变量

```bash
cp .env.example .env
```

然后检查 `.env` 中是否需要补充：

- 数据库连接配置
- 行情数据源 Token
- LLM 相关配置
- 存储路径
- Redis / MinIO 配置

### 4. 先跑测试

推荐优先使用：

```bash
.venv/bin/python -m unittest discover -s tests -p 'test_*.py'
```

如果测试没过，先修环境问题，再继续。

### 5. 启动后端服务

```bash
uvicorn quant_platform_api.main:create_app --factory --app-dir apps/api/src --host 0.0.0.0 --port 8000 --reload
```

或：

```bash
.venv/bin/uvicorn quant_platform_api.main:create_app --factory --app-dir apps/api/src --host 0.0.0.0 --port 8000 --reload
```

### 6. 健康检查

优先检查：

- `http://127.0.0.1:8000/healthz`

如果环境中已经提供 PostgreSQL / Redis / MinIO，建议补跑：

```bash
.venv/bin/python tools/verify_infra_stack.py \
  --database-url "$DATABASE_URL" \
  --redis-url "$REDIS_URL" \
  --minio-endpoint "$MINIO_ENDPOINT" \
  --app-url "$APP_PUBLIC_URL"
```

如果是远程环境，再进行端口转发或 Preview。

### 7. 打开页面

依次检查：

- `/`
- `/login`
- `/register`
- `/workspace`
- `/strategy`
- `/backtests`
- `/replay`
- `/indicators`
- `/rules`

说明：

- `/` 为公开首页
- `/login`、`/register` 为公开页面
- 其余业务页面当前为登录保护页面
- 未登录访问受保护页面时，应跳转到 `/login?next=目标路径`
- 登录后进入 `/strategy` 时，还应检查：
  - 是否能看到“市场范围”
  - 是否能看到“混合周期观察层”
  - 是否能看到 A股 / 美股 / 加密货币 / 伦敦金选项

如果你是后续 Agent，每次推进开发后，请至少更新本文件中的以下内容：

1. 最近更新时间  
2. 已完成的核心内容  
3. 当前 GitHub 主分支最新已同步提交  
4. 当前默认开发方向 / 下一开发重点  
5. 页面结构、认证方式、默认测试账号是否有变化  
6. 恢复步骤里是否需要新增页面检查、测试命令或环境说明

如果你没有同步更新本文件，就不算完成这轮接力整理。

## 十、恢复完成的判定标准

只有满足以下条件，才算恢复完成：

- 仓库已成功 clone
- 虚拟环境可用
- 测试可运行
- `healthz` 正常
- 页面可打开
- 新 Agent 已读完关键设计文档
- 新 Agent 已明确后续开发优先级

如果当前平台已经包含登录保护，还应补充检查：

- 首页可公开打开
- 登录页与注册页可打开
- 未登录访问工作台会跳转到登录页
- 默认测试账号可登录
- 登录后工作台可访问

恢复完成后，再正式进入下一轮开发。
