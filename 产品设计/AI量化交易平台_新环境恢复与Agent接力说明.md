## 一、给新 Agent 的直接指令

如果你是新环境中的 Agent，请直接按以下顺序执行，不要先让我自己判断下一步。

### 你的任务目标

你需要帮助用户完成三件事：

1. 从 GitHub 恢复当前 AI 量化交易平台项目到新环境  
2. 验证项目可以启动、测试可以运行、核心文档齐全  
3. 在恢复完成后，继续基于当前设计与代码推进开发，而不是重新做一遍选题和设计

### 你的工作方式

- 先检查用户是否已经在新环境中克隆了 GitHub 仓库
- 如果没有，就先引导用户完成 `git clone`
- 如果已经克隆完成，就直接进入环境恢复、测试验证和应用启动
- 在恢复完成之前，不要急着重构业务功能
- 在恢复完成之后，优先阅读本文件列出的关键文档，再继续开发
- 不要重新做产品规划，不要忽略已有冻结稿、实施稿、接力简报

## 四、新环境恢复步骤

如果你是新 Agent，请优先带用户执行以下步骤。

### 1. 检查关键目录

进入仓库后，先确认至少存在：

- `apps/`
- `infra/`
- `tests/`
- `tools/`
- `产品设计/`

### 2. 创建 Python 虚拟环境

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -U pip
pip install -e apps/api
```

说明：

- 当前测试和服务启动最好优先使用仓库内 `.venv`
- 如果系统 `python3` 缺依赖，优先用 `.venv/bin/python`

### 3. 准备环境变量

```bash
cp .env.example .env
```

然后检查 `.env` 中是否需要补充：

- 数据库连接配置
- 行情数据源 Token
- LLM 相关配置
- 存储路径
- Redis / MinIO 配置

### 4. 先跑测试

推荐优先使用：

```bash
.venv/bin/python -m unittest discover -s tests -p 'test_*.py'
```

如果测试没过，先修环境问题，再继续。

### 5. 启动后端服务

```bash
uvicorn quant_platform_api.main:create_app --factory --app-dir apps/api/src --host 0.0.0.0 --port 8000 --reload
```

或：

```bash
.venv/bin/uvicorn quant_platform_api.main:create_app --factory --app-dir apps/api/src --host 0.0.0.0 --port 8000 --reload
```

### 6. 健康检查

优先检查：

- `http://127.0.0.1:8000/healthz`

如果环境中已经提供 PostgreSQL / Redis / MinIO，建议补跑：

```bash
.venv/bin/python tools/verify_infra_stack.py \
  --database-url "$DATABASE_URL" \
  --redis-url "$REDIS_URL" \
  --minio-endpoint "$MINIO_ENDPOINT" \
  --app-url "$APP_PUBLIC_URL"
```

如果是远程环境，再进行端口转发或 Preview。

### 7. 打开页面

依次检查：

- `/`
- `/login`
- `/register`
- `/workspace`
- `/admin`
- `/strategy`
- `/backtests`
- `/replay`
- `/indicators`
- `/rules`

说明：

- `/` 为公开首页
- `/login`、`/register` 为公开页面
- `/admin` 为管理员专属页面
- 其余业务页面当前为登录保护页面
- 未登录访问受保护页面时，应跳转到 `/login?next=目标路径`
- 普通用户访问 `/admin` 时，应跳转回 `/workspace`
- 登录后进入 `/strategy` 时，还应检查：
  - 是否能看到“市场范围”
  - 是否能看到“混合周期观察层”
  - 是否能看到 A股 / 美股 / 加密货币 / 伦敦金选项

- 额外数据源状态：
  - 已试连 `Tushare`，当前提供的 token 调用 `trade_cal` 返回 `40203` 无接口权限，暂未接入现有数据链路。

- 同类交互已继续扩展：
  - 交易复盘中，`上传并解析 / 登记截图并生成记录 / 提交手动记录` 会先按当前来源数据是否齐备决定是否点亮；解析完成后才点亮 `运行 AI 复盘`。

## 七、给新 Agent 的行为要求

如果你是新 Agent，请遵守以下要求：

1. 不要从零开始重新做产品规划  
2. 不要把项目当成“只有一页原型”的早期状态  
3. 不要忽略 `产品设计/` 目录中的现有冻结稿和实施稿  
4. 先恢复项目，再继续开发  
5. 在继续开发时，要保持“平台化、系统化、可复现”的方向  
6. 每次改动都补测试  
7. 如果发现仓库和文档不一致，优先指出冲突并先统一基线  
8. 每次完成一轮开发推进后，必须同时更新三处记录：
   - GitHub 仓库代码
   - 仓库内 `.claude/agents/briefings/` 简报
   - 本文件《AI量化交易平台新环境恢复与Agent接力说明》
9. 以后如果用户切换 Agent，默认以“GitHub 当前代码 + 本接力文件 + 最新 briefings”为接力基线

## 十、恢复完成的判定标准

只有满足以下条件，才算恢复完成：

- 仓库已成功 clone
- 虚拟环境可用
- 测试可运行
- `healthz` 正常
- 页面可打开
- 新 Agent 已读完关键设计文档
- 新 Agent 已明确后续开发优先级

如果当前平台已经包含登录保护，还应补充检查：

- 首页可公开打开
- 登录页与注册页可打开
- 未登录访问工作台会跳转到登录页
- 默认测试账号可登录
- 登录后工作台可访问

恢复完成后，再正式进入下一轮开发。
