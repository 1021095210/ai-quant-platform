# AI 量化交易平台

这是当前可运行的仓库基线，不是纸面设计稿。平台已经具备首页、登录/注册、用户工作台、策略工坊、回测中心、交易复盘、指标设置和规则模块，前后端、数据层和部署基线都在这个仓库里。

## 核心技术回答

### 1. 前端用什么

- 当前前端不是 React、Vue 或 Streamlit。
- 现状是 `FastAPI + 多页面 HTML + Vanilla JavaScript + CSS`。
- 页面文件在 `apps/api/src/quant_platform_api/static/`，由后端统一托管。
- 这样做的原因是当前阶段优先保证研究流程、部署复杂度和接力成本可控，而不是先引入前端构建链。

### 2. 后端用什么

- 后端使用 `Python 3.11`
- Web 框架使用 `FastAPI`
- 服务进程使用 `Uvicorn`
- 数据访问层使用 `SQLAlchemy`
- 当前异步任务还是应用内任务执行器，没有拆成独立 worker 进程

### 3. 数据存哪里

- 业务元数据默认存 `SQLite`，生产/共享环境建议切到 `PostgreSQL`
- 行情缓存和市场快照当前使用独立 `SQLite` 文件
- `Redis` 已纳入部署基线，用于后续任务队列/状态缓存接入
- `MinIO` 已纳入部署基线，用于后续对象存储、导出文件、原始上传文件分层保存

### 4. 有没有 AI 组件

- 当前线上可运行链路里，策略生成和复盘仍以规则模板和结构化生成逻辑为主
- 配置层已经预留 `OpenAI 兼容 API` 接口
- 计划中的 AI 作用：
  - 自然语言策略描述转结构化 DSL
  - 交易复盘总结
  - 用户研究结论摘要
- 当前不会把原始交割单全文直接发给外部模型，仍按白名单字段控制

### 5. 怎么部署

- 本地/演示环境：Docker 镜像 + `infra/docker-compose.yml`
- 外部托管依赖环境：Docker 镜像 + `infra/docker-compose.external.yml`
- 轻量演示：也可以直接本地启动 FastAPI，再通过临时隧道公开访问

## 数据流转

### 策略生成

用户在策略工坊输入自然语言描述 -> 后端解析市场、周期、术语、混合周期上下文 -> 生成结构化 DSL、Python 样例和说明摘要 -> 用户决定是否保存为策略项目版本 -> 项目元数据写入业务数据库

### 回测

用户选择策略项目版本并填写回测配置 -> 后端生成 `config_revision` 并冻结执行参数 -> 绑定 `data_snapshot_ref` -> 读取或生成数据快照摘要 -> 调用回测引擎执行 -> 回测结果、配置摘要、快照摘要、风控/仓位结果写入任务记录 -> 工作台和回测中心读取这些结果

### 交易复盘

用户上传交割单 -> 后端保存上传记录并解析标准化成交记录 -> 复盘任务读取记录聚合结果 -> 生成交易统计、问题提示和复盘结论 -> 结果写回任务记录和上传记录

### 工作台汇总

工作台读取当前登录用户的策略项目、最近回测、最近复盘、任务状态和快照摘要 -> 后端按 `user_id / workspace_id` 过滤 -> 返回用户私有研究中枢数据

## 业务流转

### 首次使用

打开首页 -> 进入登录/注册 -> 登录后进入工作台 -> 创建第一个策略项目 -> 发起第一次回测 -> 查看结果与快照摘要

### 日常研究

登录 -> 打开工作台 -> 继续最近项目 -> 在策略工坊修改描述和规则 -> 发起新回测 -> 比较最新结果 -> 进入复盘页查看交易问题

### 管理与运维

配置环境变量 -> 选择 SQLite 或 PostgreSQL -> 校验 Redis/MinIO/应用健康状态 -> 启动服务 -> 通过 `/healthz` 和 `tools/verify_infra_stack.py` 验证依赖

## 部署入口

- 本地一体化部署：`infra/docker-compose.yml`
- 外部托管依赖部署：`infra/docker-compose.external.yml`
- 环境模板：`.env.example`、`infra/deploy.env.example`
- 依赖联调脚本：`tools/verify_infra_stack.py`

## 当前边界

- 前端仍是服务端托管静态页面，不是独立 SPA
- 真实多市场执行约束还在推进中
- Redis 和 MinIO 已进入部署基线，但业务逻辑对它们的使用仍是下一阶段重点
